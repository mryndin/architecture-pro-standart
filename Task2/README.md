# Анализ требований к цифровой трансформации банка «Стандарт» (FURPS+)

Ниже представлена классификация требований для реализации MVP по открытию депозитов и развитию кредитного направления. В таблице выделены архитектурно-значимые требования (ASR), определяющие выбор технологического стека и структуры системы.

## Архитектурные рекомендации по реализации MVP

Для успешного достижения целей бизнеса (открытие депозита за один визит или мгновенно онлайн) рекомендуется внедрить следующие решения:

1. **Единый сервис управления ставками (Product Rate Engine):**
   * Логику расчета ставок необходимо перенести из Excel-файлов в отдельный сервис. Это создаст «единый источник истины» для всех каналов и исключит ошибки ручного ввода.
   
2. **Кэширование данных (Sidecar Cache):**
   * С учетом требования по отклику в миллисекунды, справочные данные из АБС должны кэшироваться на уровне веб-сервисов (например, в Redis). Это снизит нагрузку на Oracle и уберет секундные задержки.

3. **Внедрение сквозного ID заявки (Correlation ID):**
   * Для связки процессов (сайт -> кол-центр -> отделение) необходимо использовать единый идентификатор заявки. Это позволит сотруднику фронт-офиса мгновенно найти заявку, созданную клиентом ранее на сайте.

4. **Асинхронное взаимодействие (Event-Driven):**
   * Хотя ИБ пока не совместим с Kafka, новые микросервисы для сайта и кредитных заявок следует проектировать с использованием очередей сообщений. Это позволит мгновенно передавать данные в Кредитный конвейер, не дожидаясь суточной выгрузки из АБС.
